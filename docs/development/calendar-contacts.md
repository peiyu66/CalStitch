## 4. 技術方案與待驗證事項

1. **目的行事曆與權限**：先走 iOS EventKit。已同步至 iPhone 的 Google 行事曆，預期可由系統介面使用其中有權修改的日曆，不再向 Google 重複登入。未同步者只提供設定引導。選單標示唯讀目的地、不讓它成為寫入目標。只有新增權限不足以讀回、更新和刪除；完整管理模式需使用者授予 EventKit 完整存取。以 iCloud 與已同步的 Google 測試日曆驗證，不先假設兩者行為完全一致。
2. **重算及安全對帳**：落地事件附註須含穩定且唯一的規則 ID。建議使用獨立、帶版本的完整標記行，例如 `[CalStitch:v1 rule=<規則ID> occurrence=<單次事件ID>]`；規則 ID 找出這組事件，單次事件 ID 協助更新同一期，不以日期或標題作識別。可保留任意使用者附註，更新時只處理自己的標記行。缺少、格式無效或有衝突的標記，不以同名或同日猜測，也不據此刪除。需驗證同步往返可保留標記與使用者文字。第二次套用相同規則不重複新增；改日期就更新該期，移除規則只清理可確認是本 App 產生的未來事件。全量同步可能讓目的日曆或事件的本地 ID 失效；無法辨認時暫停，不按同名日曆猜。若對帳範圍超過四年，分段查詢，避免漏掉舊事件。
3. **日期正確性**：用台灣民用日期做初版驗證。以 2027-02-06 正月初一、02-07 初二、02-20 正月十五為回歸案例。macOS Foundation 已驗證這三個日期的正反換算，iOS 和實際寫入尚未驗證。閏月及小月已採用[現行農曆規則](rules.md#section-44)，節氣則採用[規則專屬時區](rules.md#section-34)。跨帳號同步後的全天事件顯示仍待實機驗證。
4. **規則與實際寫入範圍**：規則以使用者設定的起訖為生成與維護範圍。重新套用、縮短截止或移除規則時，保留已開始的事件，只更新或移除尚未開始且可辨認為此規則建立的事件。縮短截止時也要核對舊範圍，清理原已排定、現已超出截止日的未來事件。長區間是否一次寫完或分段，待實測。初步方案是先算出個別公曆日期再寫入；不要先依賴 Apple 或 Google 能可靠保存農曆重複規則。若考慮採用原生重複，先驗證實際的寫入、讀回與同步。
5. **生日資料**：匯入保留來源曆法、月日及有提供的閏月資訊，不猜缺漏年份，不將所有非公曆生日視為中國農曆，也不以聯絡人的裝置本地 ID 當跨裝置識別碼。

## 14. 實機行事曆寫入

- 實機版不再限制為模擬器測試日曆。從規則頁或生日匯入頁可透過 iOS 取得完整行事曆存取，選擇裝置上已設定且能寫入的 EventKit 行事曆；顯示行事曆名稱及可取得的帳號來源，唯讀選項不可選。已同步至 iOS 的 Google 行事曆與 iCloud 日曆一樣由 EventKit 存取，不另要求 Google 登入。實機不建立預設日曆、不代選、不在連接時寫入事件。模擬器仍使用原有專用本機日曆。
- 按「預覽」不寫入；按「套用」或選定目的地後按「匯入並套用」才寫入。維護依規則 ID、期次標記、目的行事曆精確 ID，並核對本機已記錄的事件；保留已開始的事件和不屬於本 App 的事件。失去權限、日曆不可用、識別不一致或找不到預期事件時停止，不以同名日曆替代。
- 跨多本日曆的批次會先核對全部目的地與事件，再送出單次 EventKit 提交。編輯既有已套用規則不會把事件遷移到另一本日曆；搬移不是這版新增的功能。套用前先試寫規則快照，減少日曆寫好但規則未儲存的可能。
- 實機版可供使用者驗收行事曆寫入；實機操作只安裝，不代開 App、不替使用者同意 iOS 權限、不代按套用。
- 整日事件以最後一天收尾再交給 EventKit，避免預設把隔日凌晨也當作整日而多排一天。獨立測試以實機同一寫入路徑在既有模擬器的兩本隔離日曆驗證新增、重複套用、更新、移除、不可用目的地不寫入，以及保留手動與已開始事件；包含兩天整日與定時事件。測試通過，Air 安裝檔也已建置、簽章核對。此為該次模擬器驗證紀錄；後續安裝見版本紀錄。實機 iCloud／Google 同步仍未在本條紀錄驗證。
- 已依使用者確認，將可寫入行事曆的新版原地安裝至指定 iPhone Air，裝置上已核對 CalStitch 安裝成功。未啟動 App、未同意行事曆權限、未修改實機行事曆；實機寫入與同步仍待使用者驗收。

## 20. 試用回饋：分類預設行事曆

- 每個主分類以第一條儲存的規則所選的目的行事曆作為預設，供日後新增規則預填；不因畫面排序或次類不同而改變。刪除第一條規則，或將它移出分類時，依原儲存順序從剩餘規則找下一個仍可寫入的目的行事曆；沒有可用目的地就留空，請使用者選擇。
- 匯入生日時，已有「生日」分類即可預填其預設行事曆。個別選人和群組匯入都適用，存成草稿和匯入後套用也一致。仍可在匯入前改選，不覆蓋本次已手動選定的目的地，也不因此更改既有規則或搬移既有事件。

<a id="section-21"></a>

## 21. 試用回饋：清除遺留事件

- 在首頁「匯入生日」旁加「清除遺留事件」。掃描可寫入的行事曆，只列出附註有可解析、無衝突的 CalStitch 所有權標記，且規則 ID 已不在本機任何現存規則（含草稿、子規則）的事件。不以名稱、分類或日期猜測歸屬，不列沒有標記的事件、原生重複系列或唯讀事件。顯示實際搜尋日期範圍，不把有限結果宣稱為全部歷史。
- 分「已過去」與「未到來」兩區。每筆顯示事件名稱、日期和來源行事曆，預設不勾選，可在各區全選或個別勾選。不列正在進行中的事件。刪除前確認勾選筆數與涉及的行事曆；執行前重新讀取並核對事件標記與規則狀態，有變動就要求重新檢視。只刪勾選的遺留事件，不動任何 App 規則或未勾選事件。

<a id="section-22"></a>

## 22. 試用回饋：事件附註的規則標記格式

- 寫入規則標記時，先保留原有附註正文，再接兩個換行、獨立一行的 Markdown 分隔線 `----`、兩個換行，最後寫原格式的 CalStitch 規則標記。分隔線上下各空一行，新增標記的前綴為 `\n\n----\n\n`；規則 ID 及事件序號的格式維持不變。
- 既有沒有分隔線的標記仍須可讀、可比對，不因格式變更而批次重寫舊事件；重複套用不疊加分隔線或標記。

<a id="section-23"></a>

## 23. 試用回饋：依群組匯入生日後的分類

- iPhone Air 回報：匯入前預覽的分類「生日」與次類「群組名稱」正確，匯入後看到群組名稱成為分類。須核對同一筆新匯入規則在首頁與編輯頁的顯示，區分分類寫入錯誤與首頁層級顯示問題。預期仍為主分類「生日」、次類「群組名稱」，不批次搬動舊規則或重寫事件。
- 隔離模擬器使用虛構聯絡人驗證匯入及儲存：草稿重啟、套用單筆草稿及匯入後立即套用皆保留正確的主分類與次類，未重現寫反。此測試不含系統選群及實機顯示。首頁兩層圖示類似、只差約 5 點縮排，層級不明是待查假設；沒有讀取或修改 Air 資料。

## 25. 設定頁：預設時區與隱私權聲明

- 首頁提供設定按鈕。設定頁上方為「預設時區」：未選定時帶入目前 iOS 時區，使用者可以展開選單改選；儲存地區型時區識別碼（例如 `Asia/Taipei`），不把 UTC 偏移量存成固定值。
- 下方提供「隱私權聲明」入口，先保留頁面，正式聲明待定稿。尚未接入排程換算時應在設定頁說明，這一階段只儲存偏好，不重算任何規則，也不修改行事曆。
- 已完成設定介面：可搜尋城市或時區，也可切回「跟隨 iOS」；隱私權聲明目前為預留頁。模擬器版編譯成功，未啟動點測或安裝實機。

<a id="section-26"></a>

## 26. 試用回饋：匯入生日的事件標題

- 個別選人和群組匯入一致：新規則的預設事件標題為「聯絡人姓名＋生日」或「聯絡人姓名＋農曆生日」，直接相接、不加空格，只有農曆才特別標示。例如「黃培祐生日」與「黃培祐農曆生日」。匯入預覽、儲存為草稿和直接套用採用同一個預設標題；事後仍可編輯。
- 此命名只套用新匯入，不改既有規則或事件，不影響用來源識別及生日類型判斷是否已匯入。

## 28. 試用回饋：通訊錄授權後接續群組匯入

- Air 實測：從「依群組匯入」前往 iOS 設定開放完整存取後，按左上角返回 CalStitch，回到首頁而非原流程。預期返回「依群組匯入」並自動重新讀取群組；若仍未授權，留在授權引導，可取消。
- 現有重讀依賴原匯入畫面留在記憶體。從該畫面開啟設定時應保留一次性接續狀態，App 即使被系統重新載入也能回到原流程；取消後不再自動開啟。只恢復畫面，不自動匯入或寫行事曆。
- 尚未取得完整權限的設定引導文案改為：「群組匯入需要完整的通訊錄存取權限，請到設定變更權限。」保留前往設定、取消及改用個別選人。若設定返回已能自動重查權限，授權引導頁不再需要「重新讀取」；讀取失敗時仍建議提供「重試」。

<a id="section-36"></a>

## 36. 試用回饋：群組匯入權限提示

- 未取得完整權限時，提示改為：「群組匯入需要通訊錄的『完整取用權限』，請到『設定』變更權限。」畫面原文如下，保留全形單角引號：

  群組匯入需要通訊錄的「完整取用權限」，請到「設定」變更權限。

- 只改提示文案，不更動按鈕、授權或返回流程。

<a id="section-37"></a>

## 37. 試用回饋：生日匯入方式的樣式

- 「匯入方式」選到「草稿」時，以柔和的灰藍提示，不用紅色；「匯入後套用」維持原有配色。兩個選項的字都放大一些，保留清楚的選取狀態及無障礙可讀性。
- 不改匯入行為：仍預設草稿，只有明確選「匯入後套用」並按下匯入才寫入行事曆。

<a id="section-45"></a>

## 45. 下一版驗收：群組匯入的授權分流

- 保留已在 0.1 (8) 實作的分流：第一次按「讀取聯絡人群組」在 App 內開啟 iPhone 系統授權視窗；若選完整取用，直接列出群組。已選部分取用或拒絕才顯示「開啟設定」，返回原流程後重查；已有完整權限直接列群組。App 不自行授權，不自動匯入。
- 首次說明要讓使用者知道接下來會看到系統視窗，可在那裡選「完整取用權限」。不新增 App 自己的「同意」對話。保留「改用個別選人」與「取消」。下一版分別驗證首次授權及由設定返回。

<a id="section-48"></a>

## 48. 試用回饋：清除遺留事件的搜尋更新（待修改）

- 拿掉常駐「重新搜尋」按鈕，改以清單下拉更新。進頁、取得行事曆權限、刪除成功後仍自動搜尋；有搜尋失敗才提供「重試」。刪除前維持現行重新核對，不依賴使用者手動更新。
