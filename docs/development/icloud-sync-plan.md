# CalStitch iCloud 規則同步計畫

狀態：18 基準的同步功能已進入實機驗證；下列解除凍結與主畫面權限更新從 iPhone 開發版 23 隔離實作。以 iPhone 送審建置 **1.0 (18)** 的原始碼為基準。已另行開發的 **19 版 iPad UI 暫停且保留**，不合併、不修改；等 iPhone 的 iCloud 同步通過實機驗收並確認穩定，再接續 iPad。18 版是已送審的基準，不是已上架版本。

## 1. 範圍與使用方式

- 同一 Apple 帳號的 CalStitch 透過 CloudKit 私人資料庫同步規則，包含規則 ID、條件、分類、父子關係與排序。行事曆事件仍由各自的 iCloud 或 Google 行事曆帳號同步，不複製到 CloudKit。不直接串 Google API，不需要自建伺服器。
- 使用者在哪台按「套用」或確認刪除，就由那台取得 CloudKit 確認後更新事件。另一台收到規則只刷新清單，不因收到資料而掃描或補寫事件。首次載入以同步進度區分「尚未載入」和「確定無規則」。
- CloudKit 可用時，已儲存的規則都同步，不論指定本機或同步行事曆。沒有 iCloud 時才只保存在裝置上。裝置專用的行事曆與其事件仍留在原裝置；不跨裝置配對同名本機行事曆，CalStitch 不搬移、不轉換事件。
- 保留 18 版的規則、預覽、單筆及批次操作行為；不更動 iPad 介面，也不藉由同步擴大過去事件的清理範圍。

## 2. 從 18 版一次性遷移

- 18 版將規則存在 App 本機，目的地仍可能是 iCloud 或 Google 行事曆。升級後，在 CloudKit 可用時，將所有已儲存的舊規則遷入私人資料庫，包含指定裝置本機行事曆的規則；保留原規則 UUID、分類與順序、父子關係、最近一次成功套用的事件識別及日期範圍。既有事件留在原行事曆，不寫入、不搬移、不補建。本機目的地須保留原裝置的身分，其他裝置收到規則時不以同名行事曆代替。如果系統已將原本的本機行事曆搬到 iCloud，僅在能以既有標記核對原事件後，才承認那是新的同步目的地。
- 事件身分以「規則 ID＋單次事件識別鍵」及成功套用紀錄核對，不把舊裝置的 EventKit ID 當成跨裝置 ID。保留原識別鍵、整日／指定時間的日期語意及時區資訊；已開始的識別鍵不能因新日期落在未來而再次生成。已確認零筆和缺少舊套用紀錄必須分開；資料不足時不猜測、不重建。目的地無法辨認不阻礙規則同步；目的地狀態在各裝置獨立判定。既有已儲存草稿仍是草稿，不標成已套用。CloudKit 暫不可用時保留本機資料，待可用再重試。父子樹的規則全部遷移，不因使用不同來源的行事曆而拆分。
- 以原規則身分與帳號範圍重試遷移。只有確認同一規則已成功保存才標記遷移完成；遇到既有雲端記錄先核對，不以舊本機副本覆蓋較新的雲端修改。後續版本保留這條升級路徑，支援直接從 18 版跳升；已成功遷移的不再匯入。

## 3. 辨認行事曆與凍結

1. 啟動時檢查既有的同步規則：先查這台裝置已記住的行事曆 ID；找不到時，以帳號來源加行事曆名稱比對，應只有一本符合。事件附註中的完整規則 ID 可協助核對，不覆蓋已確認的行事曆對應。
2. 找不到、同名有歧義、唯讀或沒有完整行事曆取用權限時，在本機凍結該規則。凍結規則可查看，不能修改、套用或刪除，批次操作亦排除。父規則凍結時，下游子孫一併凍結；父規則解凍後，子孫仍須各自通過目的地及狀態檢查。只有子規則凍結時，不向上或向旁支擴散。所有操作適用同一個凍結限制：凡是要寫入的範圍包含凍結規則，就不執行該次寫入；直接操作、父子連動和批次操作都不例外。不能存取 iPhone 本機行事曆的裝置，應提示回原 iPhone 操作；不能用同名行事曆解除凍結。絕不改用預設行事曆補建。
3. 設定提供「隱藏凍結的規則」，只影響本機清單。回前景或行事曆清單有變動時可重新檢查目的地；恢復可確認且可寫後解除凍結。這是行事曆清單檢查，不是掃描事件。
4. Apple 行事曆 App 取消顯示某本行事曆，不等於停用帳號同步或變為唯讀。仍由 EventKit 回報的可用性與寫入權限判定；隱藏但可寫的情境列入實測。
5. 已確認行事曆但收不到預期舊事件，只在使用者於該台主動套用或刪除時顯示「等待行事曆同步」。不可把一時找不到當成從未建立；真正未套用、或前次已確認為零筆，要能明確辨認。

6. 使用同一個「凍結／解除凍結」流程；不另設核對中斷畫面，不詢問使用者原裝置是否還會寫。顯示可辨識的原行事曆，不提供改選、搬移或以預設行事曆取代。缺少權限、原行事曆不可用、唯讀或無法獨立核對，維持唯讀凍結，不提供只改規則或只刪規則的旁路。
7. 未確認的待完成操作依帳號與單次操作計時，寫入鎖保留；前景約每三十秒讀取，不採整份雲端紀錄的修改時間。此裝置在兩分鐘內收到權威完成結果才自動解除等待。到期仍未確認就將受影響規則記為本機手動凍結；跨前景、重開及遲到的完成結果均保留，之後只由使用者發起解除凍結。不再用該操作持續自動等待或解鎖，但其他規則正常同步。得到明確不一致立即凍結，不須等兩分鐘。計時只影響本機顯示及保護，不轉移原裝置的寫入資格、不改動事件。
8. 主畫面首次需要行事曆完整取用時先說明，由使用者開啟系統授權；未授權仍可同步及唯讀查看規則，也可開設定。曾拒絕、限制或只有寫入取用時，主畫面只提供前往系統設定，不重複跳提示。每次啟動與回前景重新檢查。缺少完整取用時，這台裝置不開放新增、編輯、套用、刪除、匯入、批次或事件預覽；不新增草稿例外，也不移除已有的生日匯入草稿功能。入口授權本身不建立模擬器行事曆。

## 4. 套用順序與中斷復原

1. **先留紀錄。** 套用或確認刪除時產生 UUID 作為「套用 ID」。本機先持久記錄規則、目的行事曆、舊與新日期、預定新增／更新／移除的事件，以及此次套用 ID。刪除在事件消失後無附註可查，須先記下預計移除的對象。
2. **先取得資格，再動事件。** 對受影響的規則或子樹使用 CloudKit 條件式儲存，依伺服器版本標記取得這次的寫入資格，並在雲端保存待完成狀態及接手所需的原套用計畫與事件識別，不保存裝置專用的 EventKit ID。兩台同時出手，只有一台能成功；另一台不動 EventKit，保留草稿、讀取新版，由使用者決定是否再套用。既有操作仍待完成時，不讓下一次操作超車。不另編數字版號，也不以時間戳記裁決。
3. **核對後寫入。** 僅操作已確認行事曆中的目標事件。新增或更新後，在附註保留原規則 ID 和本次套用 ID，保留使用者附註並向下相容舊版標記。一次套用的多筆事件共用 ID；同一次復原沿用，重新發起才換 ID。
4. **事件完成才結案。** 本機確認 EventKit 結果後才向 CloudKit 記錄完成；雲端確認完成後才清除本機待完成紀錄。刪除保留必要的刪除標記，避免另一台把尚未同步的刪除誤認為遺留事件，或把已刪規則重新帶回。
5. **啟動或回前景先看套用日誌。** 無待完成就不掃事件；若同一操作仍在執行，保持原流程；僅原操作裝置有已停止的待完成項目時，針對日誌涉及的行事曆與日期核對，只補做缺的部分。若 CloudKit 確認狀態不明，先依套用 ID 核對伺服器，不猜測已取得資格；若核對不出結果，保留待完成，不盲目重建。復原不阻塞主畫面。
6. **解除凍結，不重播。** 自動就原行事曆與權威日誌做不寫入的核對，能核對則直接顯示預覽，不另設預覽按鈕。使用者按「確認接手」只恢復這台的普通修改與刪除權；按鈕下方明示不立即改動行事曆事件。不直接重跑先前的套用或刪除；後續普通預覽及確認才寫入。不能核對時說明原因並維持凍結，不能把無預覽當成零筆。
7. **先證明安全，再結束寫入鎖。** 待完成超時但尚未確認中斷時，不能只憑時間或使用者按鍵撤回原寫入資格。確認中斷仍須確認正確可寫原行事曆、舊寫入停止的日誌證據，以及目標範圍可安全以目前有效規則及套用紀錄繼續；只在證據充分時用 CloudKit 同一操作的條件式保存結束原待完成項，與「原操作已完成」分開記錄。若缺資料、尚在同步、或現有事件不能安全核對，等候而不搬移、補建或只刪規則。 若既有事件的身分全部核對得上，只是標題或其他資料有差異，可解除凍結後依一般流程處理；查無必要事件、出現沒有舊紀錄的事件，或一般流程已無法查到的事件，仍維持凍結。原裝置返回先讀最新紀錄，原操作已被接手處理則不得重跑；原操作先完成而結果遲到時，須由使用者發起解除凍結才核對並採用最新規則，或尊重刪除標記，不回滾。
8. **先看同步日誌；保存未套用的修改。** 若日誌尚未到達，按套用才發現狀態疑似不一致，先保存本次修改以供後續處理，不替換有效規則、不寫事件。解除凍結不自動載入來源或版本無法核對的草稿，也不刪除已儲存的生日匯入草稿。只有最終的一般套用或刪除可以修改行事曆。

9. 遺留事件清除須等雲端規則及刪除標記完整載入，不得將仍有效、凍結、待完成或正在接手的規則視為遺留。

## 5. 實作與驗收順序

| 階段 | 交付與驗收 |
| --- | --- |
| 建立基準 | 從實際封存 18 的 iPhone 原始碼開始隔離開發，確認版本、目標裝置及既有測試；不可直接從含 iPad 19 工作的工作樹接著改。保存可重現的 18 基準再開工。 |
| 規則同步 | 用 CloudKit 開發環境驗證既有規則首次同步、分類與父子順序、帳號未登入／切換與離線。同步或帳號失敗不解讀為空清單；雲端規則未獲伺服器確認時不寫事件。 |
| 目的地與 UI | 驗證同源同名配對、同名歧義、裝置本機同名、只在原裝置可寫的本機目的地、父子混合目的地與向下凍結、唯讀、失去授權、隱藏但可寫；驗證凍結、隱藏、解凍及批次排除。 |
| 升級與手動解凍 | 用 18 版的舊標記測試：一筆未來受管事件、一個已開始的受管識別鍵、同日同名的一筆私人事件。升級不寫事件；重新綁定後，一般預覽只規劃更新或移除未來受管事件，且不重建已開始的事件。一般套用仍保留舊事件同步檢查；出現重複標記或行事曆無法確認時，阻擋寫入。另測遷移中斷、重試不覆蓋新版、跳版升級，以及正常待完成不可直接接手。另測中斷後先凍結，再從解除凍結發起接手，驗證缺少的未來期次會新增（例如延長一年）、舊套用 ID 不同仍可更新、已正確的不重寫；已知同步延遲、原裝置恢復及兩台同時接手時，不得多寫。 |
| 寫入與復原 | 用雙裝置或可控測試重現同時套用、規則先到但舊事件延遲或部分到達、寫完事件卻沒回報、回前景時原操作仍在執行。所有情境均不得重複新增、錯刪、寫到別本行事曆或由接收端補寫。記錄一般啟動零事件掃描，量測批次復原。 |
| iPhone 驗收 | 跑 18 版回歸，完成 iPhone 實機同步測試；啟用正式 CloudKit 或發佈前，核對實際資料流、隱私聲明與上架資料。確認 iPhone/iCloud 穩定後，才安排接續 iPad 19。 |

Apple 技術參考：[CloudKit 私人資料庫](https://developer.apple.com/documentation/cloudkit/ckcontainer/privateclouddatabase)、[條件式儲存](https://developer.apple.com/documentation/cloudkit/ckmodifyrecordsoperation/recordsavepolicy/ifserverrecordunchanged)、[EventKit 行事曆識別碼](https://developer.apple.com/documentation/eventkit/ekcalendar/calendaridentifier)。
